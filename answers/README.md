# Відповіді до лабораторної роботи № 3

1. За серверної автентифікації клієнт перевіряє сертифікат сервера. У mTLS сервер додатково перевіряє клієнтський сертифікат і доказ володіння його приватним ключем.
2. Сервер вимагає клієнтський сертифікат і перевіряє його ланцюжок довіри та призначення. За відсутності або недійсності сертифіката рукостискання завершується помилкою.
3. Кожне з’єднання починається з перевірки ідентичності обох сторін. Приватний ключ залишається у власника. Окремі сертифікати дозволяють надійно пов’язувати події з конкретними клієнтами.
4. `Subject Alternative Name` містить DNS-імена й IP-адреси, дозволені для сертифіката. Go зіставляє адресу сервера із SAN. CN у клієнтському сертифікаті тут використовується як ідентифікатор аудиту.
5. Для STARTTLS SMTP спочатку відкриває звичайне з’єднання, а після команди `STARTTLS` починає TLS-рукостискання. На порту 465 TLS зазвичай починається одразу, до SMTP-команд. Порт 587 часто використовують для подання пошти через STARTTLS.
6. Він позначає межі частин `multipart` та дозволяє поштовому клієнту окремо розібрати HTML і файл, кожен зі своїми заголовками й кодуванням.
7. Кодування перетворює довільні байти файла на набір текстових символів, придатний для передавання через поштові системи. Отримувач відновлює вихідні байти під час декодування.
8. Він приймає SMTP-листи в тестову скриньку й показує HTML, заголовки та вкладення. Розробник може перевіряти надсилання без зовнішнього поштового облікового запису.
